About Me

Senior Ruby on Rails developer and GIS/automation specialist, available fractionally or as a freelancer — experienced, independent help without agency overhead.

I specialise in the harder end of Rails work: legacy upgrades, long-running system stability, deployment and ops, and the operational problems that don't have obvious answers. A particular niche in geospatial systems — map platforms, planning and property portals, FME/Rails APIs, CAD/web integrations and geospatial automation.

What has changed is the throughput. Every part of my delivery pipeline is now agentic: implementation written in Cursor with Grok's Composer model, every pull request reviewed automatically by Copilot before I look at it, and Sentry wired into Slack so production tells us what's actually broken. The judgement about what to change — and what not to touch — is still mine. The tedious mechanical work is not.

How I Build

AI isn't a line on my invoice — it's how the work gets done

Brief first, then code

I write the spec, the constraints and the failing test. The agent works to them. Unbounded prompting is how AI-assisted projects go wrong.

Cursor + Grok Composer

The bulk of implementation is agent-written, in-repo, with the whole codebase as context — not copy-pasted from a chat window.

Copilot reviews every PR

Automated review runs on every change before a human sees it. Human review time then goes on design decisions instead of typos and missed edge cases.

Tests as the guard rail

Agentic speed is only safe with a suite that fails loudly. On legacy codebases, coverage comes before velocity — every time.

Sentry → Slack → fix

Production errors arrive in Slack with context, get triaged the same day, and are often fixed before anyone raises a ticket.

Progress where you can see it

Deploys, error rates and what changed, reported into your Slack. You shouldn't have to ask a contractor what happened this week.
